## 1. Лицензия: выбора нет, и это хорошая новость

GPL-3.0 — **копилефт**, а формулировка «v3.0» без «or later» означает, что перелицензировать нельзя:
ни в MIT/Apache, ни в AGPL-3.0, ни в «другую GNU». Производная работа обязана остаться GPL-3.0.

Что это обязывает сделать:

| Требование | Как выполняете |
|---|---|
| Сохранить `LICENSE` как есть | Файл уже не тронут — просто не менять |
| Сохранить авторство | Оставить раздел «Авторы» и Boosty-ссылку Black Triangle. Своё имя **добавить рядом**, не вместо |
| Пометить изменения и дату (GPLv3 §5a) | Файл `NOTICE` со списком выше (шаг 4) |
| Отдавать полный исходник | Ваш публичный репозиторий |
| Не добавлять ограничений | Не вводить свои условия поверх GPL (например, «только некоммерческое») |

Свою строку copyright добавить можно и уместно: `Copyright (C) 2026 <вы>` для ваших правок, рядом с
оригинальной. Это не перелицензирование.

**Чего делать нельзя:** заменять текст `LICENSE` на другой, удалять упоминания автора, публиковать
без пометки об изменениях.

## 2. Развилка: форк или отдельный репозиторий

| | **А. Форк** (рекомендую) | **Б. Отдельный репозиторий** |
|---|---|---|
| Как создать | Кнопка Fork на странице оригинала | New repository, **пустой** (без README/LICENSE!) |
| Связь с оригиналом | Видна в шапке: «forked from HelpFreedom/youthub» | Только через remote `upstream`, в UI не видно |
| Стягивать код из оригинала | Кнопка «Sync fork» + `git fetch upstream` | Только `git fetch upstream` вручную |
| Прислать правку в оригинал (PR) | **Да** | **Нет** — GitHub не даёт PR в неродственный репозиторий |
| Атрибуция по GPL | Встроена и честна | Нужно оформлять руками (`NOTICE`) |
| Ограничения | Форк публичного репо **нельзя** сделать приватным | Полный контроль |

Раз вы хотите тянуть код из оригинала — это ровно то, для чего форки и сделаны. Плюс форк
оставляет возможность однажды отдать свои починки в upstream пул-реквестом. **Берём вариант А.**

## 3. Шаги (вариант А — форк)

### Шаг 1. Удалить теги, иначе они уедут на GitHub

```
git -C /home/u/youthub tag -d v0.1.1 v0.1.2
git -C /home/u/youthub tag        # должно быть пусто
```

Я поставил эти два тега по ошибке (правило «теги не ставить, чужой клон» записано в памяти проекта).
Удаление из моего инструмента заблокировано как разрушительная git-операция — выполните сами.
**Если не удалить — они не уедут, если пушить только ветку (шаг 7 без `--tags`).** Но лучше удалить:
тег без «or later» на чужом клоне только путает.

### Шаг 2. Создать форк в веб-интерфейсе

1. Открыть `https://github.com/HelpFreedom/youthub`.
2. **Fork** → Owner = ваш аккаунт → **Create fork**.
3. Форк создастся с копией `main` на состоянии upstream.

`gh` не установлен, поэтому руками. Ставить его ради одного действия не нужно (хотя
`gh repo fork HelpFreedom/youthub --clone=false` сделал бы то же самое).

### Шаг 3. Переставить remote: upstream вместо origin

```bash
cd /home/u/youthub
git remote rename origin upstream
git remote add origin https://github.com/<ваш-логин>/youthub.git
git remote -v
```

Ожидается: `origin` — ваш форк, `upstream` — HelpFreedom. Текущая ветка `main` теперь отслеживает
`upstream/main` — это нормально, переключим на `origin/main` при пуше (`-u`).

### Шаг 4. Оформить пометку об изменениях (GPLv3 §5a)

Создать `NOTICE` в корне:

```markdown
# NOTICE

Это изменённая версия проекта **YouHub** (https://github.com/HelpFreedom/youthub),
автор оригинала — **Black Triangle**. Оригинал распространяется под GNU GPL v3.0.

Изменения внесены <ваше имя>, 2026-09-30 … 2026-10-01, и распространяются
под той же лицензией GNU GPL v3.0. Полный список изменённых файлов:

- README.md — раздел о правках
- bridge_player.py — watchdog, перемотка (карта «байты ↔ время»), уборка очереди нажатий
- po_token.mjs, sabr_bridge.mjs — контекст аттестации BotGuard (EVENT_ID)
- recs_pipeline.py — превью панели рекомендаций упаковываются в mp4
- scripts/hs_probe.py — headless-проба потока
- test_seek.py, test_watchdog.py — детерминированные тесты
- История_диалогов.md, План_*.md — рабочая документация проекта
```

Альтернатива (тоже законна, но шумнее): шапка `# Modified by …, 2026-10-01` в каждом изменённом
файле. Для 12 файлов `NOTICE` практичнее.

### Шаг 5. Поправить README, не растеряв чужое

Обязательно оставить: бейдж GPLv3, раздел «Авторы» с Black Triangle, его Boosty-ссылку.

Добавить:
- строку «Это форк `HelpFreedom/youthub`; см. `NOTICE` об изменениях»;
- свой раздел с тем, что добавлено (перемотка, аттестация, панель рекомендаций);
- по желанию — свою ссылку для поддержки рядом с оригинальной.

Строку 65 `git clone https://github.com/HelpFreedom/youthub.git` можно заменить на ваш форк, но
ссылку на оригинал стоит сохранить отдельно — иначе теряется линия авторства.

### Шаг 6. Коммит

```bash
git add NOTICE README.md История_диалогов.md
git commit -m "docs: пометка об изменениях для GPLv3 §5a, раздел о форке в README"
```

По вашему правилу «отдельная просьба — отдельный коммит» это отдельный коммит: он про лицензионную
обвязку, а не про код.

### Шаг 7. Пуш — только ветка, без тегов

```bash
git push -u origin main
```

`--tags` **не добавлять**: иначе уедут теги, которые мы убираем в шаге 1. Флаг `-u` переключит
`main` на отслеживание `origin/main`.

Пуш пройдёт fast-forward: ваш `main` — потомок `upstream/main`, а форк только что создан с той же
точки. Конфликтов быть не может.

### Шаг 8. Проверка

```bash
git remote -v                                   # origin = ваш форк, upstream = HelpFreedom
git status -sb                                  # main...origin/main, впереди 0
git log --oneline -3
git ls-files | grep -c "^cache/"                # должно быть 0 — секреты не уехали
git ls-files | grep -iE "oauth|cookies|\.env"   # должно быть пусто
```

И на GitHub: страница форка показывает «forked from HelpFreedom/youthub», в файлах есть `LICENSE`
без изменений, `NOTICE`, ваш README-раздел.

## 4. Синхронизация с оригиналом (то, ради чего это всё)

```bash
cd /home/u/youthub
git fetch upstream
git log --oneline upstream/main -5        # что нового у оригинала
git merge upstream/main                   # влить в свой main
git push origin main                      # отдать в свой форк
```

До слияния полезно посмотреть, что именно меняется: `git diff --stat main..upstream/main`.

Правила, чтобы не потерять свои 30 коммитов:

| Ситуация | Что делать |
|---|---|
| Обычное обновление | `git merge upstream/main` — свои коммиты остаются, конфликты только в пересекающихся местах |
| Конфликт в `bridge_player.py` | Ожидаемо: там наши главные правки. Разбирать по смыслу, не «взять чужое целиком» |
| Перед слиянием | Страховочная ветка: `git branch backup-before-upstream-<дата>` |
| Если upstream перепишет историю | `git rebase upstream/main` вместо merge (и `git push --force-with-lease origin main`) |

На GitHub то же самое делает кнопка **Sync fork** в шапке форка — но она делает merge только
`main`, без ваших локальных коммитов; для локальной работы всё равно нужен `git fetch upstream`.

## 5. Чего не делать

| Не делать | Почему |
|---|---|
| Менять текст `LICENSE` | Копилефт: производная обязана остаться GPL-3.0 |
| Удалять «Авторы» и Boosty Black Triangle | Нарушение GPL и просто нечестно |
| `git push --tags` | Уедут теги, которые убираем в шаге 1 |
| Публиковать без `NOTICE` | Формальное нарушение GPLv3 §5a |
| `git push --force` в `upstream` | Пуш в чужой репозиторий вообще не нужен; свои правки отдают через PR из форка |
| Коммитить `cache/` | Там `oauth.json` и куки; каталог уже в `.gitignore` — не убирать оттуда |

## 6. Что стоит знать перед публикацией

**Репутационная сторона, не юридическая.** Проект реверс-инжинирит протокол SABR и чеканит
PO-токены BotGuard в обход технических мер защиты YouTube. Экспозицию ваша публикация не меняет —
код уже открыт и у него 98 звёзд. Но теперь он связан и с вашим именем: к таким репозиториям
случаются DMCA-запросы, а автор оригинала указан как Black Triangle. Это ваше решение, просто
чтобы оно было осознанным.

**Личное в документах.** Путь `/home/u` встречается в трёх md-файлах (21 вхождение в
`История_диалогов.md`, по 2 в двух планах) — светит имя вашего локального пользователя. Не
секрет, но если не хочется — заменить на `<user>` до пуша отдельным коммитом.

**Публичный форк нельзя сделать приватным** — GitHub это запрещает для форков публичных
репозиториев. Если в будущем понадобится закрытый вариант, это будет отдельный независимый
репозиторий (вариант Б), а не форк.
