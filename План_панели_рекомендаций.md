## 1. Причина

`ffplay-yt` собран с `--disable-everything`, и в сборку **не попали ни демультиплексор для
изображений, ни декодеры JPEG/PNG**. Точная конфигурация — из самого бинарника
(`ffplay-yt/bin/ffplay-yt -nodisp -loglevel info /dev/null` печатает её первой строкой):

```
--disable-x86asm --disable-doc --disable-ffmpeg --disable-ffprobe --disable-avdevice
--disable-network --disable-postproc --disable-everything --enable-ffplay --enable-swscale
--enable-swresample --enable-avfilter --enable-protocol=file
--enable-demuxer='mov,mp4,matroska,avi,flv,webm_dash_manifest'
--enable-decoder='h264,hevc,mpeg4,aac,mp3,opus,vorbis,flac'
--enable-parser='h264,hevc,aac,mpegaudio,opus,vorbis,flac'
--enable-bsf='h264_mp4toannexb,hevc_mp4toannexb'
--enable-filter='crop,transpose,hflip,vflip,rotate,aresample,aformat'
```

Ни `image2` (демультиплексор для одиночных картинок), ни `mjpeg`/`png` (декодеры) здесь нет.

**Как это ломает панель:**

```
recs_pipeline.py отдаёт пути к .jpg и .png
        ↓  (IPC работает — панель, фокус и счётчик рисуются)
ffplay.c :: load_image_texture(path)                       (строка ~1126)
  ├─ avformat_open_input(&fmt, path, NULL, NULL)   ← НЕТ демультиплексора → ошибка
  └─ return NULL
        ↓
draw_sidebar(): t_thumb == NULL, t_text == NULL
        ↓
рисуются только плейсхолдеры (35,35,40 / 25,25,30)  → «серые прямоугольники»
```

**Доказательство (воспроизводится за секунду):**

```bash
cd /home/u/youthub
ffplay-yt/bin/ffplay-yt -nodisp -autoexit -loglevel info cache/recs_thumbs/i6uDq1VaF44.jpg
# → cache/recs_thumbs/i6uDq1VaF44.jpg: Invalid data found when processing input
ffplay-yt/bin/ffplay-yt -nodisp -autoexit -loglevel info cache/recs_text/i6uDq1VaF44.png
# → cache/recs_text/i6uDq1VaF44.png: Invalid data found when processing input
```

Ошибка молчит в `cache/play.log`, потому что probe не находит формат **до** логирования —
поэтому баг и выглядел «невидимым».

Заодно доказано, что дело именно в формате, а не в путях/правах: тот же файл, перекодированный
в `mp4`, плеер **открывает и читает метаданные** —

```bash
ffmpeg -y -i cache/recs_thumbs/i6uDq1VaF44.jpg -c:v mpeg4 -q:v 3 -frames:v 1 /tmp/t.mp4
ffplay-yt/bin/ffplay-yt -nodisp -autoexit -loglevel info /tmp/t.mp4
# → Stream #0:0: Video: mpeg4 (Simple Profile), yuv420p, 320x180   ← поток распознан
```

## 3. Два пути починки

| | **А. Быстрый обход (без пересборки)** | **Б. Правильный фикс (пересборка)** |
|---|---|---|
| Суть | отдавать картинки в формате, который сборка уже понимает — `mp4` с одним кадром (`mpeg4` или `h264`) | добавить в сборку `--enable-demuxer=image2` и `--enable-decoder=mjpeg,png` |
| Что править | `recs_pipeline.py` (Python) | `ffplay.c` не трогать; пересобрать бинарник |
| Цена | ~30 минут, риск низкий | часы: исходников FFmpeg в репозитории нет, качать и собирать 4.3.9 |
| Минусы | лишняя конвертация каждой картинки (ffmpeg-процесс), файлы тяжелее JPEG, возможны артефакты на мелком тексте | долго; нужно точно повторить конфиг сборки |
| Плюсы | панель заработает сразу; ничего не пересобирать | правильное, «как задумано»: JPEG/PNG читаются напрямую, пайплайн не меняется |

**Рекомендация:** сделать **А** (панель заработает сегодня), **Б** — опционально, как приведение
сборки в соответствие с задумкой. Если делать Б, конфиг для повторения брать **из бинарника**
(раздел 1), а не из README.

## 4. Путь А — пошагово

1. В `recs_pipeline.py` после получения превью и полосы текста конвертировать их в `.mp4`
   (`-c:v mpeg4 -q:v 3 -frames:v 1`), кэшировать результат рядом с исходником и возвращать
   путь к `.mp4`. Функции: `download_thumb()` (строка ~268), `render_text_strip()` (~288).
2. Кэш: сейчас проверка «файл уже есть» — по `.jpg`/`.png`. Добавить парный `.mp4` (и/или
   расширить проверку существования), иначе будет конвертировать каждый запуск.
3. Прогнать пайплайн вручную и убедиться, что в `RECS_ITEM` уходят пути `.mp4`:
   ```bash
   .venv/bin/python3.11 recs_pipeline.py q13s8aq__RI | head -3
   ```
4. Проверить, что плеер их рисует (раздел 5).

**Оптимизация, если конвертация окажется медленной:** кодировать сразу `-preset ultrafast`
(h264) или `-q:v 5` (mpeg4, быстрее), либо конвертировать параллельно (пайплайн и так
в отдельном потоке контроллера).

**Чего НЕ делать в пути А:** не пытаться отдать `.webp`/`.avif` (`libwebp`/`libavif` нет),
не рассчитывать на `image2` «через хитрость» — его в бинарнике нет.

## 5. Путь Б — пошагово

1. Сохранить рабочий бинарник: `cp ffplay-yt/bin/ffplay-yt ffplay-yt/bin/ffplay-yt.bak`
   (правило пользователя: прежние версии не затирать).
2. Взять исходники FFmpeg **4.3.9** (версия видна в первой строке `--version`), распаковать,
   положить `ffplay-yt/ffplay.c` поверх `fftools/ffplay.c`.
3. Собрать с **фактическим конфигом из раздела 1** плюс `--enable-demuxer=image2`
   (и `--enable-decoder=mjpeg,png`, если их там всё же нет).
4. Скопировать бинарник в `ffplay-yt/bin/ffplay-yt`, проверить:
   ```bash
   ffplay-yt/bin/ffplay-yt -nodisp -autoexit -loglevel info cache/recs_thumbs/<любой>.jpg
   # ожидаем: строка про Video: mjpeg, а не "Invalid data found"
   ```
5. Убедиться, что не сломано остальное: воспроизведение `.mkv` из потока, `-ipc`, панель.

## 6. Проверка результата (любой путь)

Без окна — открывается ли файл:

```bash
SDL_VIDEODRIVER=dummy ffplay-yt/bin/ffplay-yt -autoexit -loglevel info <файл>
```

**Готча:** `-nodisp` для этой проверки **не годится** — он отключает видео-поток целиком, и
ffplay отвечает `Failed to open file ... or configure filtergraph` даже на валидном файле.
Использовать `SDL_VIDEODRIVER=dummy` (как выше).

С окном — глазами:

1. Запустить приложение, Tab: тайлы с картинками, фокус рамкой, стрелки двигают фокус.
2. Enter открывает выбранный ролик (`PLAY_VIDEO`).
3. Прокрутка до конца догружает порцию (`LOAD_MORE_RECS` → `CONTINUATION`).
4. Скриншот приложить к записи в `История_диалогов.md`.

Скриншот окна:

```bash
DISPLAY=:0 import -window "$(DISPLAY=:0 xdotool search --name 'ffplay' | head -1)" /tmp/sidebar.png
```

## 7. Антипаттерны

| Не делать | Почему |
|---|---|
| Верить конфигурации сборки из README | README описывает **другую** сборку (`…,mjpeg,png`, `vp9,libdav1d`), чем реально в бинарнике. Истина — `--version` самого бинарника |
| Считать баг проблемой IPC или пайплайна | данные и фокус доходят; ломается только загрузка картинок |
| Проверять через `-nodisp` | отключает видео-поток и даёт ложную ошибку |
| Пересобирать плеер ради проверки гипотезы | сначала `--version` и тест на одном файле — отвечают за секунды |
| Гонять SABR-сессии ради этого бага | панель к потоку не относится |
| Затирать рабочий бинарник при пересборке | сохранить копию |
| Убивать окно плеера через `pkill -f` | остаётся осиротевший мост; выход — `q` или `kill <PID>` |
| Коммитить пачку правок одним коммитом | одна просьба — один коммит |

## 8. Инструменты

| Инструмент | Назначение |
|---|---|
| `ffplay-yt/bin/ffplay-yt -nodisp -loglevel info /dev/null` | печатает **фактическую конфигурацию сборки** |
| `ffplay-yt/bin/ffplay-yt -nodisp -autoexit -loglevel info <файл>` | «понимает ли плеер этот файл» |
| `SDL_VIDEODRIVER=dummy …` | то же, но без искажения от `-nodisp` |
| `recs_pipeline.py <vid>` | ручной прогон пайплайна, видны пути в `RECS_ITEM` |
| `cache/play.log` | лог контроллера, stderr плеера идёт туда же |
| `ffprobe`, `file` | валидность и формат исходных картинок |
| `import -window`, `xdotool search --name` | скриншот окна для приёмки |
