# План устранения бага: панель рекомендаций в ffplay-yt пуста

**Для кого этот документ:** для ИИ-ассистента, который продолжит работу над `/home/u/youthub`.
Читать целиком перед началом. Факты ниже проверены на этой машине 2026-10-01 — не переоткрывать.

**Симптом (со слов пользователя):** «на панели рекомендаций в ffplay ничего не отображается».

**Важно:** этот баг **не связан с потоком YouTube**. Панель можно отлаживать на любом локальном
видеофайле, не тратя ни одной SABR-сессии. Не смешивать с `План_решения_стены.md` — там другая,
уже закрытая история.

**Второе важное:** каталога `ffplay-yt/src/` (исходники FFmpeg 4.3.9, из которых собран плеер)
в репозитории **нет** — только `ffplay-yt/ffplay.c` и готовый бинарник. Любая правка в `ffplay.c`
требует заново скачать и собрать FFmpeg 4.3.9 (README, раздел «4. Сборка ffplay-yt»). Это долго,
поэтому **все безборочные способы диагностики идут раньше** любого инструментирования C-кода.

## 1. Как панель устроена (карта данных)

```
recs_pipeline.py                     печатает в stdout:
  ├─ fetch_recs_authed/unauth          CLEAR_RECS
  ├─ download_thumb()   → cache/recs_thumbs/<id>.jpg
  ├─ render_text_strip() → cache/recs_text/<id>.png
  └─ print(...)                        RECS_ITEM <id>\t<thumb>\t<text>
                                       CONTINUATION <token>
        │
        ▼  stdout читается построчно
bridge_player.py :: LivePlayer._run_recs_subprocess()          (строка ~645)
  ├─ CLEAR_RECS / RECS_ITEM → self._send_ipc(line)             (строки ~659, ~672)
  └─ CONTINUATION           → self._recs_continuation (в плеер НЕ идёт)
        │
        ▼  unix-сокет, который плеер СОЗДАЁТ и СЛУШАЕТ (bind/listen, ffplay.c ~2706-2724)
ffplay-yt :: ipc thread
  ├─ "CLEAR_RECS"  → recs_count=0, recs_cleared_flag=1          (строка 2523)
  ├─ "RECS_ITEM "  → парсит два таба → recs_items[]            (строка 2531)
  └─ "LOAD_MORE_RECS" ← отправляет плеер, когда фокус у конца списка
        │
        ▼
ffplay-yt :: draw_sidebar()                                     (строка 1788)
  └─ load_image_texture() — через ffmpeg (avcodec+swscale), не SDL_image
```

Панель включается клавишей **Tab** (`sidebar_mode` → `start_sidebar_anim`), вызывается
`draw_sidebar` при `sidebar_offset_px > 0` (строка 2288). Загрузку данных можно выключить
переменной `SIDEBAR_RECS=0` (`bridge_player.py:158`).

**Что видно при разных состояниях:**
- `recs_count == 0` → только тёмный фон панели (18,18,22). **Пусто, без прямоугольников.**
- `recs_count > 0`, текстура не загрузилась → серые плейсхолдеры (35,35,40 / 25,25,30), строка ~1826.

## 3. Гипотезы, по убыванию вероятности

| # | Гипотеза | Чем подтвердится |
|---|---|---|
| **A** | `_send_ipc()` молча теряет строки: `sendall` падает, возвращаемый `False` никто не проверяет (`bridge_player.py:414-421`) | отправлено > 0, принято плеером = 0 |
| **B** | В приложении пайплайн отдаёт пустой `items`, но есть `next_token` → `return 0` **без единого `RECS_ITEM`** (`recs_pipeline.py:405-410`) | в логе `recs done`, но ручной запуск с тем же id даёт элементы |
| **C** | Плеер не читает IPC (поток заблокирован / сокет пересоздан) | строки уходят, `recs_count` = 0 |
| **D** | Строки доходят, но текстуры не грузятся | на экране **серые плейсхолдеры**, а не пустота |
| **E** | Панель не открывается (Tab / анимация `sidebar_offset_px`) | не видно даже фона и разделителя |

Приоритет — **A и B**: обе дают ровно «пусто без плейсхолдеров».

## 4. Этапы

### Этап 0. Ручной прогон плеера — **первым делом** (без пересборки)

Разделяет все гипотезы одним действием и не требует ни YouTube, ни сборки.

```bash
cd /home/u/youthub
# тестовое видео, чтобы не зависеть от потока:
ffmpeg -f lavfi -i testsrc=size=640x360:rate=25 -t 60 -y /tmp/probe.mp4

# плеер — ровно так, как его поднимает контроллер:
ffplay-yt/bin/ffplay-yt -hide_banner -loglevel warning \
  -ipc /tmp/probe.ipc.sock -x 1280 -y 720 -i /tmp/probe.mp4
```

Во втором терминале — послать то, что в норме шлёт контроллер:

```bash
cd /home/u/youthub && python3.11 - <<'PY'
import os, socket, time
T = os.path.abspath("cache/recs_thumbs/i6uDq1VaF44.jpg")
X = os.path.abspath("cache/recs_text/i6uDq1VaF44.png")
s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
s.connect("/tmp/probe.ipc.sock")
s.sendall(b"CLEAR_RECS\n")
for i in range(3):
    s.sendall(f"RECS_ITEM vid{i}\t{T}\t{X}\n".encode())
    time.sleep(0.2)
print("sent")
PY
```

Затем **Tab** в окне плеера и скриншот:

```bash
DISPLAY=:0 import -window "$(DISPLAY=:0 xdotool search --name 'ffplay' | head -1)" /tmp/sidebar_shot.png
```

Прочитать PNG глазами:

| Что на скриншоте | Вывод | Дальше |
|---|---|---|
| 3 тайла с картинками | плеер и отрисовка исправны → баг в передаче | этап 1 (A/B/C) |
| 3 серых прямоугольника | передача исправна, не грузятся картинки | (D) → этап 2 |
| ничего (только фон) | строки не дошли или фокус/анимация | этап 1, затем (E) |

### Этап 1. Инструментировать Python-сторону (тоже без пересборки)

Оба стыка на стороне Python не логируются — оттого баг и «невидим».

1. `bridge_player.py:414` `_send_ipc()` — не глотать ошибку молча:
   ```python
   def _send_ipc(self, line: str) -> bool:
       s = self._ctrl_sock
       if s is None:
           return False        # ← логировать: "[ipc] no socket, dropped: ..."
       try:
           s.sendall(("...").encode())
           return True
       except Exception as e:
           return False        # ← логировать: f"[ipc] send failed: {e}"
   ```
2. `_run_recs_subprocess()` (~645) — считать пересланное:
   ```python
   sent = 0
   ...
   if line.startswith("RECS_ITEM"): sent += 1
   ...
   cprint(f"[sidebar] {label}: {sent} RECS_ITEM forwarded")
   ```
3. `recs_pipeline.py:405` — различать «нет элементов» и «нет продолжения»: печатать
   `len(items)` и наличие токена в stderr (он попадает в `[sidebar] … rc=…`).

Затем один прогон приложения и сопоставить числа: **отдал пайплайн → переслал контроллер →
принял плеер**. Расхождение на первом переходе = (B), на втором = (A).

### Этап 2. Локализовать по результату

| Подтвердилась | Что проверять |
|---|---|
| **A** | жизненный цикл `self._ctrl_sock`: пайплайн стартует **после** `_connect_ipc()` (`bridge_player.py:429-436`), гонки при старте нет — значит искать разрыв соединения позже (закрытие по `_shutdown`, перезапуск плеера) |
| **B** | сравнить вывод пайплайна в приложении и вручную с тем же id; проверить, не отдаёт ли InnerTube items без continuation (кэш `pr_*`/`innertube_*`) |
| **C** | поднять плеер с `-loglevel info` и убедиться, что `ipc: listening on …` есть; проверить, не блокирует ли IPC-поток что-то в цикле плеера |
| **D** | в `load_image_texture` временно логировать причину `goto done` (какой из шагов: `avformat_open_input` / поиск декодера / `sws`/`SDL_CreateTexture`); проверить `cwd` плеера (`cwd=PROJECT_DIR`) и права на файлы |
| **E** | `start_sidebar_anim` / `update_sidebar_offset` (строка ~161, ~150): доходит ли `sidebar_offset_px` до `sidebar_width` |

### Этап 3. Пересборка плеера — только если причина в C-коде

Правка `ffplay.c` без пересборки ничего не даст. Порядок:

1. Скопировать рабочий бинарник: `cp ffplay-yt/bin/ffplay-yt ffplay-yt/bin/ffplay-yt.bak`
   (правило пользователя: прежние версии не затирать).
2. Собрать по README, раздел «4. Сборка ffplay-yt» (FFmpeg 4.3.9 + патч `ffplay.c`,
   `./configure --disable-everything …`, `make ffplay`, копирование в `ffplay-yt/bin/ffplay-yt`).
3. Зависимости сборки: `build-essential nasm libsdl2-dev libdav1d-dev libopus-dev
   libavcodec-dev libavformat-dev libswscale-dev libavutil-dev`.
4. Проверить, что новый бинарник линкуется так же: `ldd ffplay-yt/bin/ffplay-yt`
   (в эталоне — только `libSDL2-2.0.so.0` из внешних SDL; SDL_image и SDL_ttf НЕ используются).

### Этап 4. Приёмка

1. Запуск приложения, Tab — тайлы видны.
2. Стрелки двигают фокус, Enter открывает ролик (`PLAY_VIDEO` → контроллер перезапускает плеер).
3. Прокрутка до конца списка догружает порцию (`LOAD_MORE_RECS` → `CONTINUATION`).
4. Скриншот приложен к записи в `История_диалогов.md`.

## 5. Антипаттерны

| Не делать | Почему |
|---|---|
| Гонять SABR-сессии ради этого бага | панель к потоку не относится; отлаживать на локальном файле |
| Пересобирать плеер «на всякий случай» | исходников FFmpeg в репозитории нет — это долгая сборка; сначала этапы 0-2 |
| Затирать рабочий бинарник при пересборке | правило пользователя: прежние версии сохранять |
| Править `recs_pipeline.py`, не проверив его ручным запуском | он проверен и работает |
| Убивать окно плеера через `pkill -f` | остаётся осиротевший мост, и убивается собственная оболочка; выход — `q` или `kill <PID>` |
| Искать причину чтением `ffplay.c` | статический анализ уже сделан, бага в коде не видно — нужен рантайм |
| Коммитить пачку правок одним коммитом | одна просьба — один коммит |
